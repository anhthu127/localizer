# Conventions

## Files and names

- `snake_case.ts` / `snake_case.tsx`. Exceptions, both generated by shadcn and
  left under its names: everything in `src/components/ui/`, and
  `src/hooks/use-mobile.ts`.
- One component per file, named for the file: `translation_row.tsx` exports
  `TranslationRow`.
- `@/*` is `src/*`, aliased in `vite.config.ts` and `tsconfig*.json`. App code
  uses it.
- **`src/mock/` and `server/` do not.** They import with relative paths and
  explicit `.ts` extensions (`../lib/locale_data.ts`), because Node runs those
  files directly and resolves no alias. A type-only import may still use `@/`,
  since it is erased. `validation.ts` shows both in one file.
- No `index.ts` barrels. Not in `hooks/`, not anywhere — import the file.

## Comments

Source carries no explanatory comments. What survives:

- A **header docblock** saying what a module is for and why it is shaped that
  way — the file map is generated from these, so a wrong one propagates.
- A comment on a decision a reader would otherwise undo: why the mock is loaded
  dynamically, why `ms.json` is wrong on purpose, why a check is skipped for
  short strings.

Descriptive prose about what the code does belongs in `.claude/context/`, not
beside the code. A file with no header gets its line in
`.claude/context/file_map.overrides.json` instead.

## Hooks

- One hook per request a screen makes: `use_translation_rows`, `use_templates`,
  `use_coverage`, `use_target_bundles`.
- They all return the same shape — `{ data, isLoading, error, reload }`, named
  for their data. `reload()` refetches the same arguments; call it after a
  write. The old rows stay on screen until the new ones land, because the table
  is often behind an open dialog when a save triggers one.
- Do not call a hook from inside another hook unless it is genuinely necessary.
  Call both from the component.
- No folder `index`. No global store, no query cache: a screen's data is
  whatever its hook last fetched.

## State

`useState` in the page, passed down. Components below a page take props and
call callbacks; they do not fetch. The three that break this — the add-key,
export and template dialogs — call `lib/api.ts` directly because they own a
single write and nothing else needs its result; they take `reload` from the
page and call it when they are done.

## Errors

Everything from the API arrives as an `ApiError` or an `Error`, and reaches the
screen through `messageOf(cause)` as a plain sentence. Screens show it inline
where the data would have been, or as a `sonner` toast for a failed write.
Never show a status code.

## Styling

- Tailwind v4, configured in CSS. There is no `tailwind.config.js`; the tokens
  live in `src/index.css` and the theme is `class`-based via next-themes.
- Use the semantic tokens (`bg-background`, `text-muted-foreground`,
  `border-border`), not raw palette colours, so dark mode keeps working.
- Compose classes with `cn()` from `@/lib/utils`.
- Variants go through `class-variance-authority`, the way the shadcn components
  already do it.
- Motion comes from `src/lib/motion.ts` and the wrappers in
  `components/motion/`. Do not write a bespoke transition; `MotionProvider`
  already honours `prefers-reduced-motion`.
- Icons are `lucide-react`. Toasts are `sonner`. Both are already wired.

## Types

- `verbatimModuleSyntax` is on: a type import is `import type`.
- `noUnusedLocals` and `noUnusedParameters` are on, so an unused import fails
  `npm run build`. shadcn sometimes generates `import * as React` unused —
  delete the line.
- Prefer a union of string literals over an enum; `erasableSyntaxOnly` forbids
  the enum anyway.
- Shared shapes live in `lib/`, not in a component file, when both sides use
  them.

## Locale files

When a key has to exist in the seed, add the English string to
`sample-data/locale/en.json` only. The other twelve files are filled by the
import path or left empty on purpose — an empty value is what makes the key
show up as *missing*, which is the state a translator is looking for.

## Before you finish

```sh
npm run build        # the real gate: type errors and unused imports
npm run lint         # oxlint
npm run context:map  # if you added, moved or deleted a file
```
