# Localizer redesign — agent entry point

The replacement for the legacy CRA translator in `../localization-web/translator`.
A translator opens an app, picks a language, and fills in strings; a dashboard
says how far along every language is; an export hands the result back as a zip.

**Context here is routed, not searched.** Everything an agent needs to place a
change is written down and indexed below. Read the rows for the task, then open
the files they name. Do not start a task by grepping the tree — if the router
sends you somewhere wrong, fix the router as part of the change.

## Read first, always

| File | What it settles |
| --- | --- |
| `.claude/context/architecture.md` | The layers, which way dependencies point, and the four boundaries not to cross |
| `.claude/context/domain.md` | What a target, key, group, bundle, status and template are — the words the code uses |
| `.claude/context/conventions.md` | Naming, file style, comments, hooks, state, lint |
| `.claude/context/file_map.md` | Every source file, one line each. Generated — `npm run context:map` |

## Then, by task

| Task | Read |
| --- | --- |
| Add or change an API route | `.claude/context/recipes/api_route.md`, then `src/lib/api_types.ts`, `src/mock/router.ts`, `src/lib/api.ts` |
| Add a target, a screen or a route | `.claude/context/recipes/screen.md`, then `src/config/nav_items.ts`, `src/config/target_profiles.ts`, `src/App.tsx` |
| Change what *missing*, a valid key, or a check means | `src/lib/locale_data.ts`, `src/lib/validation.ts` — and nothing in `src/mock/`, which imports them |
| Touch message templates (email / SMS / notification) | `.claude/context/domain.md` § Template, then `src/lib/template_data.ts`, `src/lib/template_preview.ts`, `src/components/templates/` |
| Add a UI primitive | `npx shadcn@latest add <component>`; `components.json` holds the style. Do not hand-write one into `src/components/ui/` |
| Change the mock’s data or seeding | `src/mock/store.ts`, `src/mock/file_store.ts`, `sample-data/`; re-seed with `npm run mock:reset` |
| Work out *why* something is shaped this way | `docs/redesign_brief.md`, `docs/target_apps_ui.md`, `docs/progress_report.md` |
| Compare against the legacy app | `../localization-web/translator` and `../localization-web/docs/legacy_feature_brief.md`; `docs/redesign_brief.md` § 1 summarises it |

`README.md` is the human-facing document: stack, setup, the mock backend and
deploying. It is not duplicated here; read it when the question is "how do I run
this", not "where does this change go".

## Commands

```sh
nvm use 24          # Node 20+ required; the repo pins 24
npm run dev         # app on :5173, mock API on /api
npm run build       # tsc -b && vite build — the type check that matters
npm run lint        # oxlint
npm run context:map # regenerate .claude/context/file_map.md
npm run mock:reset  # delete server-data/, re-seeded on the next request
```

There are no tests. `npm run build` is the gate — it type-checks with
`noUnusedLocals`, so an unused import fails the build.

## Hard rules

1. `src/lib/api.ts` is the only module that knows a server exists. No screen,
   hook or component calls `fetch`, and none of them imports from `src/mock/`.
2. Domain rules — `statusOf`, `isValidKey`, `checkTranslation`, the template
   field schemas — are defined in `src/lib/` and imported by the mock backend.
   Never restate one on the other side.
3. `src/components/ui/` is generated by shadcn. Regenerate it; do not hand-edit
   it, and do not put app logic in it.
4. Every key-bearing route is scoped to one target, because each target is its
   own key namespace. `web/school` and `app/parent` can both define `nav.home`.
5. Source carries no explanatory comments. A docblock is for an algorithm's
   rationale or a public contract; everything descriptive belongs in
   `.claude/context/`.
6. Files are `snake_case.ts`. The exceptions are `src/components/ui/` and
   `src/hooks/use-mobile.ts`, which shadcn generates under its own names.

## Keeping this true

A change that adds, moves or deletes a file ends with `npm run context:map`. A
change that moves a boundary — a new layer, a new rule about who may import
what — updates `.claude/context/architecture.md` in the same commit. The router
above is part of the code: stale rows are a defect, not documentation debt.
